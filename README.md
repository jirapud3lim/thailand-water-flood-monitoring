# Thailand Water Flood Monitoring

โครงตั้งต้นสำหรับระบบติดตามน้ำท่วมประเทศไทยแบบ near real-time ซึ่งย้ายแนวคิดจาก
standalone dashboard มาเป็น FastAPI backend และ Leaflet frontend

## ความสามารถใน MVP

- แผนที่ประเทศไทยด้วย Leaflet สลับพื้นหลังได้ระหว่างแผนที่ (OpenStreetMap) และภาพดาวเทียม (Esri World Imagery)
  ไทล์ที่ไม่ตัดกับประเทศไทยจะไม่โหลด และแผนที่นอกเส้นเขตแดนถูกบังด้วยรูปทรง
  [Natural Earth Admin-0 ระดับ 1:10m](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-admin-0-countries/)
  (ข้อมูล public domain; เป็นเส้นเขตแดนสำหรับแผนที่ ไม่ใช่หลักฐานเขตแดนทางกฎหมาย)
- ชั้นความสูงภูมิประเทศแบบเปิด/ปิด (ค่าเริ่มต้นปิด) ใช้ [Mapzen Terrain Tiles บน AWS Open Data](https://registry.opendata.aws/terrain-tiles/)
  ผ่าน `GET /api/v1/terrain/tiles/{z}/{x}/{y}.png` และแปลง [Terrarium PNG](https://github.com/tilezen/joerd/blob/master/docs/formats.md)
  เป็นสี 0–5, 5–20, 20–100, 100–500 และ 500+ เมตร; คลิกแผนที่ขณะเปิดชั้นเพื่ออ่านค่าประมาณที่จุดนั้น
  สีนี้คือความสูงสัมบูรณ์ ไม่ใช่ระดับเสี่ยงน้ำท่วม และไม่เปลี่ยนคะแนน/สีจุดเตือน
  ข้อมูลไทยใช้ GMTED เมื่อมองไกลและ SRTM เมื่อซูมเข้า (~30 ม.); เป็นข้อมูลภูมิประเทศย้อนหลัง
  ไม่เหมาะตัดสินความสูงถนนหรือบ้านรายหลัง และไม่ควรเทียบกับระดับน้ำสถานีโดยไม่ตรวจหลักอ้างอิงแนวดิ่ง
  ค่าติดลบถูกซ่อนเพื่อไม่ระบายทะเลเป็นพื้นที่ต่ำ จึงไม่ใช่แผนที่พื้นที่ต่ำกว่าระดับทะเลที่ครบถ้วน
- ชั้นการจราจร (TomTom Traffic Flow) ผ่าน backend proxy เมื่อตั้งค่า `TOMTOM_API_KEY`
- ทิศทางน้ำในแม่น้ำ (`GET /api/v1/river-flow`): เชื่อมสถานี ThaiWater ในแม่น้ำเดียวกันจากต้นน้ำไปท้ายน้ำ
  โดยเรียงตามระดับน้ำ ม.รทก. (น้ำไหลจากที่สูงไปที่ต่ำ) ลูกศรสีส้มเมื่อสถานีต้นน้ำกำลังขึ้น และ popup ของสถานีบอก
  สถานีต้นน้ำ/ท้ายน้ำ ช่วงที่ระดับน้ำต่ำกว่า 2.5 ม.รทก. ถือเป็นช่วงน้ำทะเลหนุนและไม่ระบุทิศ ไม่คาดเวลาที่น้ำจะมาถึง
  และเส้นเป็นเส้นตรงเชื่อมสถานี ไม่ใช่แนวลำน้ำจริง (`backend/app/services/river_flow.py`)
- radar ย้อนหลัง 2 ชม. จาก RainViewer เล่นแบบ Windy: แถบเวลาด้านล่างแผนที่ (เล่น/หยุด, ลากเลือกเวลา, ความเร็ว 1×/2×/0.5×)
  โหลดทุกเฟรมไว้ล่วงหน้าแล้ว cross-fade จึงไม่กระตุก tile ผ่าน `GET /api/v1/radar/tiles/{frame}/{z}/{x}/{y}.png`
  ซึ่ง cache ฝั่ง server (ภาพย้อนหลังไม่เปลี่ยน) และคุมการเรียกต้นทางไม่เกิน 90 ครั้ง/นาที เพราะ RainViewer รุ่นฟรี
  จำกัด 100 ครั้ง/IP/นาที และ zoom ≤ 7 (ใช้ tile 512 px จึงคมถึง zoom 8 เกินจากนั้นภาพถูกเบลอนุ่มแทนแตกเป็นบล็อก)
  ไม่มีเรดาร์ล่วงหน้า (nowcast) เพราะ RainViewer ตัดออกจากรุ่นฟรีตั้งแต่ 1 ม.ค. 2026
- สภาพฝนปัจจุบันจาก Open-Meteo เมื่อคลิกบนแผนที่
- river discharge จาก Open-Meteo Flood API (GloFAS) เมื่อคลิกบนแผนที่
- ปริมาณน้ำในเขื่อนขนาดใหญ่จากกรมชลประทาน พร้อม icon และรายละเอียดรายจุด
- จุดเฝ้าระวังน้ำท่วมทั่วประเทศ แบ่งสีตามระดับความรุนแรง
- ข่าวน้ำและฝนจาก JSON feed กรมประชาสัมพันธ์ แสดงกับจังหวัดที่มีจุดเตือนในมุมมองหรือจังหวัดที่เลือก
  (`GET /api/v1/local-news?province=...`) กรองคำเกี่ยวกับน้ำ/ฝนและชื่อจังหวัดจากเนื้อข่าว จำกัดอายุ 7 วัน
  และแสดงลิงก์ต้นทาง ไม่ใช้ข่าวเป็นเกณฑ์ตัดสินระดับเตือน อาจไม่พบข่าวแม้มีเหตุการณ์จริง
  แหล่ง: [รายชื่อสำนักงานประชาสัมพันธ์จังหวัด](https://www.prd.go.th/th/weblink/item/index/id/3)
  และ RSS/JSON feed หมวดข่าวประชาสัมพันธ์ (`cid/9`) ของแต่ละจังหวัด; กรุงเทพฯ ใช้ feed กลาง
  การจับคู่ทำได้ระดับจังหวัดเท่านั้น ไม่อนุมานว่าอำเภอ ตำบล หรือสถานีในข่าวได้รับผลกระทบ
- ลิงก์คลิปข่าวจาก [News NBT2HD](https://www.youtube.com/@newsnbt2hd) ในจังหวัดที่มีจุดเตือน
  (`GET /api/v1/local-social?province=...`) ใช้ [YouTube Atom feed](https://developers.google.com/youtube/v3/guides/push_notifications)
  ของช่องที่ตรวจสอบแล้ว ไม่ต้องใช้ API key; กรองหัวข้อน้ำ/ฝน อายุไม่เกิน 7 วัน และชื่อจังหวัดในชื่อคลิปหรือคำอธิบาย
  feed แสดงเพียงคลิปล่าสุดของช่อง จึงอาจไม่พบคลิปแม้ช่องเคยเผยแพร่ข่าวพื้นที่นั้น
  ลิงก์เปิด YouTube โดยตรง ไม่ฝังคลิป ไม่ใช้คลิปเป็นหลักฐานยืนยันจุดน้ำท่วมหรือเปลี่ยนระดับเตือน
- จุดวัดน้ำท่วมถนนกรุงเทพฯ ซึ่งแสดงความลึกเป็นเซนติเมตรเมื่อแหล่งข้อมูลมีค่า
- สถานีโทรมาตรจากคลังข้อมูลน้ำแห่งชาติ (ThaiWater / สสน.): ระดับน้ำแม่น้ำทั่วประเทศ,
  ฝนสะสม 24 ชม., ระดับน้ำคลอง กทม. และประตูระบายน้ำ (ไม่ต้องใช้ API key) — ระดับ (severity) ของคลอง
  วัดเทียบกับตลิ่งจริง (ถึงตลิ่ง = วิกฤต, ห่างไม่เกิน 0.3 ม. = สูง) ไม่ใช่ `warning_level`/`critical_level`
  ที่ ThaiWater ให้มา เพราะค่านั้นต่ำกว่าตลิ่งมากในหลายสถานี (น่าจะเป็นเกณฑ์เริ่มสูบน้ำ ยังไม่มีเอกสารยืนยัน)
  ดู `canal_severity()` ใน `backend/app/services/thaiwater.py`
- แผง "ชั้นภาพบนแผนที่" รวมสวิตช์เรดาร์พร้อมช่วงเวลา/เล่นภาพ, น้ำท่วมจากภาพดาวเทียมพร้อมช่วงย้อนหลัง,
  พื้นที่น้ำท่วมซ้ำซาก และตัวกรองหมุดไว้ด้วยกัน; เมนูด้านข้างเหลือหมุดสถานีและเขื่อน
- ตัวกรองหมุด "เฉพาะจุดถึงเกณฑ์" (ค่าเริ่มต้น: เปิด) ซ่อนจุด ปภ./ThaiWater ที่เป็นปกติ เฝ้าระวังต่ำ
  หรือไม่มีข้อมูล ให้เหลือเฉพาะเฝ้าระวังขึ้นไป — ฝนใช้เกณฑ์เข้มกว่าคือ > 35 มม./24 ชม. เท่านั้น
  ระบบกรองฝั่งหน้าเว็บจากข้อมูลที่โหลดไว้แล้ว ไม่เรียก API ซ้ำ; สถานีที่กำลังโฟกัสหรือเปิด popup อยู่
  จะไม่ถูกซ่อนขณะเปิดตัวกรอง (ดู `RISK_LEVELS`/`isRiskVisible` ใน `frontend/app.js`); ปิดตัวกรองเพื่อดูจุดอื่น
  (ค่าที่เลือกจำไว้ที่ `localStorage` คีย์ `marker-mode`)
- น้ำท่วมจากดาวเทียม GISTDA (SAR) เลือกช่วง 1/3/7/30 วัน, พื้นที่น้ำท่วมซ้ำซาก และรายการตำบลที่ได้รับผลกระทบเมื่อซูมเข้า
- cache ฝั่ง backend พร้อม stale fallback เพื่อลดการเรียก upstream และลดอาการแผนที่ค้าง
- รายการ "จุดที่ควรดูในพื้นที่" เลือกขอบเขตได้ทั้ง "ทั้งหมดในจอ" หรือรายจังหวัด (77 จังหวัด เรียงตามจำนวนจุดเตือน)
  ผ่าน `GET /api/v1/alerts?province=...` นับสถานีละหนึ่งครั้ง โดยรวมสถานีของ ปภ. กับ ThaiWater ที่เป็นสถานีเดียวกัน
  และรวมสถานีที่มีเฉพาะใน ThaiWater ด้วย เกณฑ์เดียวกับสวิตช์ "แสดงเฉพาะจุดเสี่ยง" บนแผนที่ (เฝ้าระวังขึ้นไปเท่านั้น
  ตัดระดับ "เฝ้าระวังต่ำ" ของจุด ปภ. เช่นน้ำขังถนน 1–9 ซม. ออก) ส่วนตารางจังหวัด (รหัสและกรอบพิกัด) อยู่ที่ `GET /api/v1/provinces`
- ข้อมูลเขื่อนแสดงบนแผนที่ ทั้งป้าย % ที่หมุด และกล่องเขื่อนลอยที่เรียงตาม % ปริมาณน้ำเทียบความจุที่ระดับเก็บกักปกติ
  พร้อมภาพเขื่อนจริงจาก Wikimedia Commons (`GET /api/v1/dams/photos`) ภาพคัดด้วยมือไว้ใน
  `backend/app/data/dam_photos.json` ส่วนใบอนุญาตและผู้ถ่ายอ่านจาก Commons ทุกครั้ง และตัดภาพที่ไม่ใช่ใบอนุญาตเปิดออก
- health endpoint และ automated tests ขั้นต้น

API ที่เพิ่มสำหรับชั้นข้อมูลจุด:

```text
GET /api/v1/dams
GET /api/v1/flood-points?min_lon=...&min_lat=...&max_lon=...&max_lat=...
GET /api/v1/thaiwater/{layer}?min_lon=...&min_lat=...&max_lon=...&max_lat=...
    layer = water-level | rain | canal | watergate
```

ทุก endpoint ข้อมูลตอบรูปแบบเดิม `{data, stale}` และเพิ่ม `meta`:

```json
"meta": {"source": "dams", "status": "live|cached|stale|not_configured",
         "fetched_at": "2026-09-27T15:10:02+07:00", "observed_at_max": "2026-09-27T15:00+07:00",
         "ttl_seconds": 3600}
```

`status = "partial"` หมายถึงบาง feed ย่อยล่ม (เช่น จุดวัดถนนของ ปภ.) แต่ส่วนที่เหลือยังใช้ได้
ถ้าต้นทางล่มและไม่มี cache เลย endpoint ตอบ `503` พร้อม `detail.status = "error"`
ส่วนสถานะของทุกแหล่งดูได้ที่ `GET /api/v1/sources/status` (อ่านจาก cache ไม่ยิงต้นทาง;
มี TTL และตัวนับ hit/miss/stale/error ต่อแหล่ง)

### Cache, payload และ conditional request

- TTL แยกรายแหล่งอยู่ที่ `DEFAULT_REFRESH_TTL` ใน `backend/app/config.py` ตั้งจากผลวัดจริง 27 ก.ย. 2026
  (คลอง 5 นาที → 100 s; แม่น้ำ/ประตูน้ำ/เรดาร์ 10 นาที → 200 s; จุด ปภ. ~15 นาที → 300 s)
  ฝนรายชั่วโมงและแหล่งรายวันยังใช้ค่าเผื่อไว้ จนกว่าจะวัดข้ามต้นชั่วโมงได้
  override บางแหล่งผ่าน env: `REFRESH_TTL='{"thaiwater-canal": 100}'`
- `/flood-points` และ `/thaiwater/*` ดึงข้อมูลทั้งประเทศครั้งเดียวต่อ TTL แล้วกรอง viewport ใน backend
  จำนวนครั้งที่ยิงต้นทางจึงไม่ขึ้นกับจำนวนผู้ใช้หรือการเลื่อนแผนที่
- `?alerts_only=true` คืนเฉพาะจุดระดับเตือน (flood-points: low ขึ้นไป, ThaiWater: moderate ขึ้นไป)
  `meta` บอก `total_national`, `total_in_bbox`, `returned_count`
- Response > 1 KB ถูกบีบอัด GZip และทุก response มี `ETag` + `Cache-Control: no-cache`
  ส่ง `If-None-Match` กลับมาแล้วข้อมูลไม่เปลี่ยนจะได้ `304` ไม่มี body
  (ตัวอย่างฝน 4,436 สถานี: 2.35 MB → 87 KB gzip → 24 KB เมื่อ `alerts_only`)
- Upstream ที่ timeout / 5xx / 429 ถูก retry แบบ backoff (`UPSTREAM_RETRIES`, ค่าเริ่มต้น 1); 4xx อื่นไม่ retry
- ArcGIS ถูกดึงต่อหน้า (`resultOffset`) เมื่อผลเกิน 2,000 จุด
- ThaiWater ตรวจอายุข้อมูลซ้ำทุกครั้งที่ตอบ ข้อมูลเกินอายุจะไม่กลับมาแม้ยังอยู่ใน cache
- เขื่อนที่ RID รายงานแต่จับคู่พิกัดไม่ได้ถูกนับใน `meta.unmatched_count` ไม่หายเงียบ
- เวลา `DATA_DT` ของจุดน้ำท่วมถนน ปภ. เป็น UTC (ตาม metadata ของ layer) backend แปลงเป็นเวลาไทยใน
  `observed_at` และเก็บค่าต้นทางไว้ใน `observed_at_utc`
`/api/v1/health` ตรวจเฉพาะว่าแอปทำงาน

### วัดรอบอัปเดตของต้นทาง

ตั้ง TTL จากข้อมูลจริงด้วยสคริปต์ (ต้องรันจากเครือข่ายในไทย):

```bash
python scripts/probe_cadence.py --interval 60 --duration 3h --out data/cadence.csv
python scripts/probe_cadence.py --summarize data/cadence.csv
```

ชั้น ThaiWater ดึงข้อมูลระดับประเทศครั้งเดียวต่อ TTL (5–10 นาที) แล้วกรองตาม viewport
ใน backend จึงไม่ยิง upstream ทุกครั้งที่เลื่อนแผนที่ สถานีที่ข้อมูลเก่ากว่ากำหนด
(คลอง/ประตูระบายน้ำ 6 ชม., แม่น้ำ 24 ชม., ฝน 26 ชม.) จะถูกตัดทิ้งอัตโนมัติ

| ชั้นข้อมูล | เกณฑ์สี |
|---|---|
| ระดับน้ำแม่น้ำ | % ความจุลำน้ำ: >100 วิกฤต (ล้นตลิ่ง) · ≥90 สูง · ≥70 เฝ้าระวัง · ต่ำกว่านั้นปกติ (upstream ส่งทุกสถานี ~800 จุด; ซูมออกแสดงเฉพาะจุดเฝ้าระวังขึ้นไป) |
| ฝน 24 ชม. | เกณฑ์กรมอุตุฯ: >90 มม. วิกฤต · >35 สูง · >10 เฝ้าระวัง · >0 ฝนเล็กน้อย |
| คลอง กทม. | เทียบระดับเตือนภัย/วิกฤตของสถานี (ถ้าไม่มีเกณฑ์จะเป็นสีเทา) |
| ประตูระบายน้ำ | แสดงระดับหน้า/ท้ายประตู ไม่จัดระดับความรุนแรง |

> River discharge เป็นสัญญาณเชิงอุทกวิทยาความละเอียดประมาณ 5 กม. ไม่ใช่การยืนยัน
> ว่าจุดนั้นกำลังมีน้ำท่วม

## เริ่มใช้งาน

ต้องใช้ Python 3.11+

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn backend.app.main:app --reload
```

จากนั้นเปิด <http://127.0.0.1:8000>

รันชุดทดสอบ:

```bash
pytest
node --test tests/frontend/*.test.mjs   # กฎนับ/ซ่อนหมุด การรวมหมุด และข้อความสถานะ (frontend/rules.js)
```

## ตั้งค่า GISTDA

สมัคร API key ที่ [GISTDA Disaster Platform](https://disaster.gistda.or.th/services/open-api)
แล้วกำหนดใน `.env`

```dotenv
GISTDA_API_KEY=replace-me
```

สิ่งที่เปิดใช้ได้เมื่อตั้งค่าแล้ว:

- `GET /api/v1/gistda/tiles/{layer}/{z}/{x}/{y}.png` ส่งต่อ tile จาก GISTDA โดยเก็บ key
  ไว้ฝั่ง server เท่านั้น `layer` คือ `flood-1day`, `flood-3days`, `flood-7days`,
  `flood-30days` หรือ `flood-freq` (น้ำท่วมซ้ำซาก) tile มีขนาด 512 px
- `GET /api/v1/flood/current?window=3days` ให้จำนวนช่องน้ำท่วมในกรอบแผนที่ ถ้าใส่
  `detail=true` จะได้ช่อง H3 (ประมาณ 0.12 ตร.กม.) พร้อมผลกระทบ (ประชากร อาคาร
  โรงพยาบาล โรงเรียน ถนน นาข้าว) และ `areas` ซึ่งรวมผลเป็นรายตำบล ส่งได้สูงสุด 3,000 ช่อง
  ต่อคำขอ ถ้าเกินจะตั้ง `truncated: true`

ข้อจำกัดของข้อมูลที่ต้องแจ้งผู้ใช้:

- ข้อมูลมาจากดาวเทียมเรดาร์ (Sentinel-1, RADARSAT-2 และดวงอื่น) และช่วงข้อมูลสร้างใหม่
  วันละครั้ง จึงช้ากว่าเวลาจริงประมาณครึ่งถึงหนึ่งวัน เวลาถ่ายภาพอ่านจาก `file_name`
- ช่วง `1day` ว่างทุกครั้งที่ดาวเทียมผ่านครั้งล่าสุดเกิน 24 ชั่วโมง การไม่มีช่องน้ำท่วม
  จึงไม่ใช่การยืนยันว่าไม่มีน้ำท่วม
- ดาวเทียมเรดาร์มองไม่เห็นน้ำขังระหว่างอาคาร กรุงเทพฯ จึงได้ 0 ช่องเสมอ ต้องใช้จุดวัด
  น้ำท่วมถนนแทน

เมื่อยังไม่ตั้งค่า `/api/v1/flood/current` จะตอบ GeoJSON ว่างพร้อม
`source_status: "not_configured"` และปิดสวิตช์ชั้น GISTDA พร้อมแสดงเหตุผล

## ตั้งค่าชั้นการจราจร

ปุ่ม "การจราจร" บนแผนที่ใช้ TomTom Traffic Flow tiles ต้องมี API key จาก
[TomTom Developer Portal](https://developer.tomtom.com/) แล้วกำหนดใน `.env`

```dotenv
TOMTOM_API_KEY=replace-me
```

Browser โหลด tile ผ่าน `GET /api/v1/traffic/tiles/{z}/{x}/{y}.png` ทำให้ key อยู่ฝั่ง
server เท่านั้น ถ้ายังไม่ตั้งค่า `GET /api/v1/traffic/status` จะตอบ `configured: false`
และปุ่มการจราจรจะถูกปิดใช้งาน

## ตั้งค่าพยากรณ์ฝนกรมอุตุนิยมวิทยา (TMD NWP)

ขอ token ที่ [TMD NWP API](https://data.tmd.go.th/nwpapi/doc/index.html) แล้วกำหนดใน `.env`
(ชื่อ `TDM_API_KEY` ก็ใช้ได้เช่นกัน)

```dotenv
TMD_API_KEY=replace-me
```

- `GET /api/v1/forecast/provinces` ให้ฝนพยากรณ์รายวันของ 77 จังหวัด (วันนี้และอีก 2 วัน) ใช้
  ประมาณ 460 datapoint ต่อรอบ และเก็บ cache ไว้ 3 ชั่วโมง
- `GET /api/v1/forecast/tambon?province=&district=&subdistrict=` ให้ฝนพยากรณ์รายชั่วโมง 24 ชั่วโมง
  ของตำบล ใช้กับตำบลที่ GISTDA พบน้ำท่วม
- `GET /api/v1/areas?parent_code=` ให้รายการจังหวัด อำเภอ/เขต และตำบล/แขวงแบบไล่ระดับ
  จากทะเบียนพื้นที่ ปภ. ที่เก็บไว้ในโปรเจกต์
- `GET /api/v1/forecast/hourly?area_code=730608&hours=24` ให้ฝนพยากรณ์รายชั่วโมง 24 หรือ 48 ชั่วโมง
  ณ จุดอ้างอิงของจังหวัด อำเภอ หรือตำบลที่ตรวจรหัสแล้ว หน้าเว็บเรียกข้อมูลเมื่อผู้ใช้กดดูเท่านั้น
- คำขอ 24 ชั่วโมงใช้ประมาณ 27 datapoint เพราะดึงเวลาสำรอง 3 ชั่วโมงสำหรับ cache ระบบเก็บ cache
  1 ชั่วโมงและตัดเฉพาะชั่วโมงอนาคตก่อนตอบ
- โควตาของ TMD คือ 100,000 datapoint และ 60 คำขอต่อนาที ระบบตั้งเพดานภายใน 50 คำขอต่อนาที
  และสำรอง 5,000 datapoint ปรับได้ด้วย `TMD_REQUESTS_PER_MINUTE` และ `TMD_QUOTA_RESERVE`
  ส่วนเหลือและ metrics ล่าสุดดูได้ที่ `sources/status` (`tmd.quota`, `tmd.metrics`)
- เป็นค่าจากแบบจำลอง ไม่ใช่ประกาศเตือนภัย หน้าเว็บติดป้าย "พยากรณ์ (กรมอุตุฯ)" ทุกจุด ระดับฝน
  ใช้เกณฑ์ฝน 24 ชั่วโมงของกรมอุตุฯ (ปานกลาง >10, หนัก >35, หนักมาก >90 มม.) รหัสสภาพอากาศรายวัน
  บางครั้งขัดกับปริมาณฝน จึงไม่นำมาแสดง
