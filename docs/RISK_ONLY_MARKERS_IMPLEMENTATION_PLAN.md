# แผนพัฒนา: แสดงเฉพาะจุดเสี่ยงบนแผนที่

วันที่จัดทำ: 27 กันยายน 2026
สถานะ: **ทำเสร็จแล้ว (27 กันยายน 2026)** — ดูหัวข้อ 11

## 1. เป้าหมายและขอบเขต

ตอนนี้แผนที่มีจุดเกือบ 6,000 จุด และส่วนใหญ่เป็นระดับปกติ จึงอ่านยาก เป้าหมายคือให้ค่าเริ่มต้นแสดงเฉพาะสถานีที่มีความเสี่ยง และให้ผู้ใช้เปิดดูทุกจุดได้ด้วยสวิตช์เดียว

ขอบเขต:

- ใช้กับชั้นข้อมูลที่มีระดับภัย ได้แก่ จุด ปภ. / RID, ThaiWater ระดับน้ำ, ThaiWater คลอง และ ThaiWater ฝน
- ไม่ใช้กับเขื่อนและประตูน้ำ เพราะเป็นสิ่งปลูกสร้าง ไม่มีระดับภัย
- ไม่ใช้กับชั้นแบบ tile ได้แก่ เรดาร์ GISTDA และการจราจร
- ไม่เปลี่ยนการคลิกดูข้อมูลที่จุดใดก็ได้
- รายการ "จุดที่ควรดูในพื้นที่" และ KPI จุดเตือนใช้นิยามจุดเสี่ยงเดียวกับแผนที่สำหรับจุด ปภ. คือตัดระดับ `low` ออก (หัวข้อ 5.3 ข้อ 4)

## 2. ข้อมูลจริงที่ใช้ตัดสินใจ

ข้อมูลจาก server ในเครื่องวันที่ 27 กันยายน 2026 นับทั้งประเทศ:

| ชั้นข้อมูล | ทั้งหมด | ระดับภัยที่พบ |
|---|---:|---|
| จุด ปภ. / RID | 485 | ปกติ 352 · ต่ำ 1 · เฝ้าระวัง 61 · สูง 16 · วิกฤต 44 · ไม่มีข้อมูล 11 |
| ThaiWater ระดับน้ำ | 792 | ปกติ 521 · เฝ้าระวัง 134 · สูง 45 · วิกฤต 77 · ไม่มีข้อมูล 15 |
| ThaiWater คลอง | 217 | ปกติ 108 · สูง 16 · วิกฤต 88 · ไม่มีข้อมูล 5 |
| ThaiWater ฝน | 4,443 | 0 มม. 1,544 · ต่ำ 1,609 · เฝ้าระวัง 869 · สูง 345 · วิกฤต 76 |
| ThaiWater ประตูน้ำ | 12 | ไม่มีข้อมูลทั้งหมด |
| เขื่อน | 35 | ไม่มีระดับภัย |

ข้อสังเกต:

1. ถ้าซ่อนเฉพาะระดับปกติ ยังเหลือสถานีฝนระดับเฝ้าระวังขึ้นไป 1,290 จุด ฝนจึงต้องใช้เกณฑ์เข้มกว่าชั้นอื่น
2. เกณฑ์ฝนมาจาก `rain_severity()` ใช้ชั้นฝน 24 ชั่วโมงของกรมอุตุนิยมวิทยา คือ เฝ้าระวัง > 10 มม. สูง > 35 มม. และวิกฤต > 90 มม.
3. คลองวิกฤต 88 จาก 217 สถานี คือประมาณ 40% ซึ่งสูงผิดปกติ ดูหัวข้อ 4

## 3. นิยาม "จุดเสี่ยง" ต่อชั้นข้อมูล

| ชั้นข้อมูล | แสดงในโหมดจุดเสี่ยง | จำนวนโดยประมาณ (ทั่วประเทศ) |
|---|---|---:|
| จุด ปภ. / RID | เฝ้าระวัง สูง วิกฤต | 121 |
| ThaiWater ระดับน้ำ | เฝ้าระวัง สูง วิกฤต | 256 |
| ThaiWater คลอง | เฝ้าระวัง สูง วิกฤต หลังแก้เกณฑ์ในหัวข้อ 4 | ประมาณ 24 |
| ThaiWater ฝน | สูง วิกฤต (> 35 มม. ใน 24 ชั่วโมง) | 421 |
| ประตูน้ำ, เขื่อน | ไม่กรอง | 12, 35 |

ระดับที่ซ่อนในโหมดจุดเสี่ยง คือ ปกติ เฝ้าระวังต่ำ และไม่มีข้อมูล ส่วนสถานีฝนซ่อนระดับเฝ้าระวังด้วย

กฎตาม zoom ที่มีอยู่แล้วยังใช้ต่อ และใช้ร่วมกับโหมดแบบ AND:

- zoom ≤ 6: ฝนแสดงเฉพาะวิกฤต และระดับน้ำแสดงเฉพาะสูงกับวิกฤต
- คลองและประตูน้ำไม่แสดงเมื่อ zoom ≤ 6

ในโหมด "แสดงทุกจุด" ใช้กฎเดิมทั้งหมด ได้แก่ `minZoom` รายชั้น `RAIN_ZERO_MIN_ZOOM` และ `zoom <= 7` ของจุด ปภ.

## 4. Phase 0: แก้เกณฑ์ความรุนแรงของคลอง

### หลักฐาน

- สถานีคลอง 210 จาก 217 อยู่ในกรุงเทพมหานคร
- 124 สถานีตั้ง `critical_level` ต่ำกว่าระดับตลิ่งเกิน 0.5 ม. ตัวอย่าง:
  - ค.ลาดโตนด: warning 0.1, critical 0.2, ตลิ่ง 1.0
  - ค.บางเตย: warning 0.4, critical 0.5, ตลิ่ง 1.8
- ถ้าเทียบระดับน้ำกับตลิ่ง สถานีวิกฤต 88 แห่งแบ่งได้ดังนี้:
  - ถึงหรือเกินตลิ่ง: 7
  - ต่ำกว่าตลิ่งไม่เกิน 0.3 ม.: 17
  - เกิน `critical_level` แต่ยังต่ำกว่าตลิ่งมาก: 71
- 16 สถานีมีระดับตลิ่งเป็น null หรือ 0 ซึ่งไม่น่าเป็นค่าจริง

### สมมติฐาน

`warning_level` / `critical_level` ของคลองกรุงเทพน่าจะเป็นระดับควบคุมการระบายน้ำ คือระดับที่ควรเริ่มสูบน้ำ ไม่ใช่ระดับน้ำล้นตลิ่ง ยังไม่มีเอกสาร ThaiWater หรือสำนักการระบายน้ำ กทม. ยืนยัน

**การตัดสินใจ:** ผู้ใช้อนุมัติให้ใช้เกณฑ์ที่เทียบกับตลิ่งด้านล่าง แม้ยังไม่มีเอกสารยืนยัน

### เกณฑ์ใหม่ที่เสนอ (`canal_severity`)

| เงื่อนไข | ระดับ |
|---|---|
| ระดับน้ำ ≥ ตลิ่ง | วิกฤต |
| ตลิ่ง − ระดับน้ำ ≤ 0.3 ม. | สูง |
| ระดับน้ำ ≥ `critical_level` | เฝ้าระวังต่ำ (ซ่อนในโหมดจุดเสี่ยง) |
| ระดับน้ำ ≥ `warning_level` | ปกติ |
| ไม่มีตลิ่งหรือตลิ่ง ≤ 0 และไม่มีเกณฑ์อื่น | ไม่มีข้อมูล |
| ไม่มีตลิ่ง แต่มี `critical_level` | ใช้ขั้น "เฝ้าระวังต่ำ" เป็นระดับสูงสุด |

- ระยะ 0.3 ม. ผู้ใช้อนุมัติแล้ว ประกาศเป็นค่าคงที่ `CANAL_BANK_MARGIN_M` เพื่อปรับภายหลัง
- ป้ายใน popup เปลี่ยนจาก "ระดับเตือนภัย / ระดับวิกฤต" เป็น "เกณฑ์ ThaiWater (เตือน / วิกฤต)" และเพิ่มหมายเหตุว่าระดับบนแผนที่เทียบกับตลิ่ง เพราะยังไม่ยืนยันว่าเป็นระดับควบคุมการระบายน้ำ
- เพิ่มแถว "ห่างจากตลิ่ง" ใน popup คลอง

**เกณฑ์ผ่าน Phase 0:** คลองระดับเฝ้าระวังขึ้นไปลดจาก 104 เหลือประมาณ 24 และทุกสถานีระดับวิกฤตมีน้ำถึงตลิ่งจริง

## 5. Phase 1: โหมดแสดงจุด (frontend)

### 5.1 สวิตช์

- เพิ่มสวิตช์ `#risk-only-toggle` ชื่อ "แสดงเฉพาะจุดเสี่ยง" ไว้บนสุดของส่วน "ชั้นข้อมูล"
  - ใช้ markup `layer-control` เดิม
  - ค่าเริ่มต้นคือเปิด
- จำค่าด้วย `storage` เดิม ใช้ key `marker-mode`
- เมื่อสลับโหมด ให้วาดใหม่จากข้อมูลที่โหลดไว้แล้ว ไม่เรียก API ซ้ำ

### 5.2 ฟังก์ชันกลาง

เพิ่มกฎไว้ที่เดียว:

```js
const RISK_LEVELS = {
  "flood-points": new Set(["moderate", "high", "critical"]),
  "water-level": new Set(["moderate", "high", "critical"]),
  canal: new Set(["moderate", "high", "critical"]),
  rain: new Set(["high", "critical"]),
};
const isRiskVisible = (layer, severity) => !RISK_LEVELS[layer] || RISK_LEVELS[layer].has(severity);
```

ประตูน้ำไม่มี key ใน `RISK_LEVELS` จึงไม่ถูกกรอง

### 5.3 จุดที่ต้องแก้

1. **`loadThaiWater(layer)`**
   - เก็บ `features` ล่าสุดไว้ใน `cfg.features`
   - แยกการกรองและวาดออกเป็น `renderThaiWater(layer)` เพื่อใช้ตอนสลับโหมด
   - ในโหมดจุดเสี่ยง ให้ `visible` = กฎ zoom เดิม AND `isRiskVisible`
2. **`loadFloodPoints()`**
   - ใช้ `isRiskVisible("flood-points", p.severity)` แทนเงื่อนไข `zoom <= 7` ในโหมดจุดเสี่ยง
   - เก็บ `allFeatures` ไว้วาดใหม่ตอนสลับโหมด
3. **สถานีคู่ (`syncTwinMarkers`)**
   - `state.twDrawnIds` ต้องเป็นชุดที่วาดจริงหลังกรองแล้ว ซึ่งโค้ดเดิมทำอยู่แล้ว
   - ระดับของหมุด ปภ. เป็นค่าหลังรวมคู่ที่ใหม่กว่าแล้ว จึงไม่เกิดกรณีที่คู่หนึ่งถูกซ่อนแต่อีกฝั่งยังแสดงระดับเก่า
   - ต้องทดสอบทั้ง 3 กรณีในหัวข้อ 7
4. **ตัด `low` ออกจากรายการจุดสำคัญ (backend)**
   - ใน `backend/app/api/routes.py` ให้ `FLOOD_POINT_ALERTS` = `{"moderate", "high", "critical"}` เท่ากับ `STATION_ALERTS`
   - ระดับ `low` ของจุด ปภ. คือน้ำขังถนน 1–9 ซม. (`_road_severity`) ตอนนี้มี 1 จุด
   - ผลกระทบ:
     - `/alerts` ไม่คืนจุด `low`
     - `by_province` ไม่นับจุด `low`
     - KPI "จุดเตือน" ลดลงตามจำนวนจุด `low`
     - `/flood-points?alerts_only=true` ไม่คืนจุด `low`
   - ลบ `"low"` ออกจาก `SEVERITY_RANK` หรือคงไว้ก็ได้ เพราะไม่มีผลหลังกรองแล้ว ให้ลบเพื่อไม่ให้เข้าใจผิด
   - แก้คำอธิบาย `alerts_only` ของ `/flood-points` จาก "low..critical" เป็น "moderate..critical"
   - รายการจุดสำคัญและแผนที่จึงใช้นิยามเดียวกัน ทุกสถานีในรายการมีหมุดบนแผนที่เสมอ
5. **Popup ที่เปิดอยู่และการโฟกัส (`state.forceVisible`)**
   - ถ้าสลับโหมดขณะเปิด popup ของสถานีที่จะถูกซ่อน ให้คงสถานีนั้นไว้จนกว่า popup จะปิด
   - `focusPriority` ตั้ง `forceVisible` ด้วย เพื่อกันกรณีที่ข้อมูล `/alerts` กับชั้นแผนที่มาจาก cache คนละรอบ แล้วระดับไม่ตรงกันชั่วคราว

### 5.4 ข้อความจำนวนจุด

- **บรรทัดใต้แต่ละชั้น ThaiWater (`setTwMeta`)**
  - ตัวอย่างโหมดจุดเสี่ยง: "เสี่ยง 38 สถานี · ซ่อน 112 (ปกติ 108 · ไม่มีข้อมูล 4)"
  - บรรทัดของฝนเขียนว่า "ฝน > 35 มม."
  - ตัวอย่างโหมดทุกจุด: ใช้ข้อความเดิม
- **`updateLayerCounts()` ของจุด ปภ.:** ใช้รูปแบบเดียวกัน
- **Legend:** เพิ่มหมายเหตุ "ค่าเริ่มต้นแสดงเฉพาะจุดเฝ้าระวังขึ้นไป (ฝน > 35 มม.) · จุดที่ซ่อนไม่ได้แปลว่าปลอดภัย พื้นที่นั้นอาจไม่มีสถานี"

### 5.5 ไม่เปลี่ยน

- เก็บตัวกรองไว้ฝั่ง client
- ไม่ใช้ `alerts_only` ของ API ด้วยเหตุผลสองข้อ:
  - ต้องใช้ข้อมูลเต็มเพื่อนับจุดที่ซ่อนแยกตามระดับ
  - การสลับโหมดต้องทำได้ทันทีโดยไม่โหลดใหม่
- ถ้าภายหลังพบว่า payload ของฝนใหญ่จนช้า ค่อยเพิ่มพารามิเตอร์ที่คืนเฉพาะจุดเสี่ยงพร้อม `counts` แยกตามระดับ

## 7. ชุดทดสอบขั้นต่ำ

### Backend (pytest)

- `canal_severity` ครอบคลุม:
  - ถึงตลิ่ง
  - อยู่ในระยะ 0.3 ม. จากตลิ่ง
  - เกิน `critical_level` แต่ต่ำกว่าตลิ่งมาก
  - ตลิ่งเป็น 0 หรือ null
  - ไม่มีเกณฑ์ใดเลย
- เทสต์ `test_canal_severity_falls_back_to_bank_level` เดิมต้องยังผ่าน หรือปรับตามเกณฑ์ใหม่พร้อมเหตุผล
- `/alerts`: จุด ปภ. ระดับ `low` ไม่อยู่ใน `features` และไม่ถูกนับใน `by_province`
- `/flood-points?alerts_only=true`: ไม่คืนจุด `low`
- เทสต์ทั้งหมดต้องผ่าน (ปัจจุบัน 123 รายการ)

### Frontend (headless Chromium ผ่าน CDP)

1. เปิดหน้าแรก: สวิตช์เปิดอยู่ และไม่มีสถานีระดับปกติ ต่ำ หรือไม่มีข้อมูลบนแผนที่ ยกเว้นประตูน้ำและเขื่อน
2. สถานีฝนที่แสดงทุกจุดมี `rain_24h_mm` > 35
3. ปิดสวิตช์: จำนวนจุดกลับเท่ากับพฤติกรรมเดิมที่ zoom เดียวกัน โดยไม่มีคำขอ API ใหม่
4. reload: โหมดที่เลือกยังอยู่
5. สถานีคู่:
   - ThaiWater ปกติ และ ปภ. ปกติ: ไม่แสดงทั้งคู่
   - ThaiWater เสี่ยง: แสดงเฉพาะ ThaiWater
   - ปิดชั้น ThaiWater: หมุด ปภ. ที่เสี่ยงกลับมา
6. คลิกรายการจุดสำคัญทุกกลุ่ม: popup เปิดได้ และไม่มีรายการระดับ `low`
7. เปิด popup แล้วสลับโหมด: popup ไม่หาย
8. คลิก marker ได้ 100% ทุกชั้น (ใช้สคริปต์ click_markers เดิม) และไม่มี console error
9. ข้อความจำนวนจุดที่ซ่อนตรงกับจำนวนจริง

3. ตัดระดับ `low` ออกจาก `/alerts` ให้ตรงกับแผนที่: **อนุมัติ** ทำพร้อม Phase 0 เพราะเป็นงาน backend (รายละเอียดในหัวข้อ 5.3 ข้อ 4)

## 10. ลำดับลงมือ

1. Phase 0: เกณฑ์คลอง และตัด `low` ออกจาก `/alerts` พร้อมเทสต์ backend
2. Phase 1: สวิตช์และตัวกรองพร้อมทดสอบใน headless browser
3. Phase 2: เอกสาร

แต่ละขั้นต้องผ่านเทสต์ก่อนไปขั้นถัดไป
