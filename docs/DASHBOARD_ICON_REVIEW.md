# Dashboard Icon and Category Review

วันที่ตรวจสอบ: 27 กันยายน 2026

## สรุป

ไอคอนปัจจุบันช่วยให้รายการมีจุดสังเกตทางสายตา แต่หลายตัวเป็นอักขระ Unicode เชิงนามธรรมและไม่สื่อความหมายได้ด้วยตัวเอง ผู้ใช้ต้องอ่านข้อความกำกับเพื่อแยกประเภทข้อมูล นอกจากนี้ สัญลักษณ์เดียวกันถูกใช้ในหลายบริบท และสีชุดเดียวกันมีความหมายต่างกันระหว่างสถานีน้ำกับเขื่อน

ข้อเสนอหลักคือแยกการสื่อสารออกเป็นสองมิติอย่างชัดเจน:

1. **ประเภทข้อมูล** ใช้ไอคอนเฉพาะหมวด เช่น เรดาร์ ดาวเทียม เขื่อน และสถานีฝน
2. **ระดับสถานการณ์** ใช้รูปทรง สี และข้อความที่เรียงลำดับจากปกติถึงวิกฤต

## ปัญหาที่พบ

### 1. สัญลักษณ์เดียวมีหลายความหมาย

สัญลักษณ์ `≈` ถูกใช้เป็นโลโก้ระบบ ไอคอน KPI จุดเตือน ไอคอนจุดเฝ้าระวัง และสัญลักษณ์ระดับเฝ้าระวัง ผู้ใช้จึงไม่สามารถเรียนรู้ความหมายคงที่ของสัญลักษณ์นี้ได้

### 2. ไอคอนหมวดข้อมูลตีความได้ยาก

ไอคอน `▧`, `▦`, `▰`, `⌇` และ `⊟` ไม่ได้สื่อถึงดาวเทียม พื้นที่น้ำท่วมซ้ำซาก เขื่อน คลอง หรือประตูระบายน้ำอย่างชัดเจน หากซ่อนข้อความกำกับ ผู้ใช้ส่วนใหญ่ไม่น่าจะแยกประเภทได้ถูกต้อง

### 3. Unicode แสดงผลไม่สม่ำเสมอ

รูปร่าง น้ำหนัก และตำแหน่งของ Unicode อาจต่างกันตามระบบปฏิบัติการ เบราว์เซอร์ และฟอนต์ ทำให้ไอคอนบางตัวมีขนาดหรือแนวเส้นไม่สอดคล้องกัน

### 4. ลำดับความรุนแรงไม่เป็นระบบ

ชุด `○`, `·`, `≈`, `▲`, `!`, `?` ไม่ได้เพิ่มความเด่นตามระดับอย่างสม่ำเสมอ โดยเฉพาะ `·` ซึ่งมองเห็นยากบนแผนที่ และ `≈` ซึ่งสื่อถึงน้ำมากกว่าระดับเฝ้าระวัง

### 5. สีของเขื่อนอาจถูกตีความเป็นระดับภัย

สีแดงและสีส้มของเขื่อนหมายถึงปริมาณกักเก็บสูง แต่สีเดียวกันบนสถานีน้ำหมายถึงระดับสูงหรือวิกฤต ผู้ใช้อาจตีความว่าเขื่อนกำลังเกิดเหตุอันตราย ทั้งที่สถานะเป็นเพียงสัดส่วนความจุ

### 6. Legend ครอบคลุมไม่ครบ

หัวข้อปัจจุบันระบุว่า “สัญลักษณ์จุด ปภ.” แต่แผนที่มีข้อมูลจาก ThaiWater, RID, GISTDA และ RainViewer ด้วย ข้อความที่บอกว่า ThaiWater ใช้สีตามเกณฑ์รายชั้นยังไม่อธิบายรูปร่าง สี และข้อยกเว้นของแต่ละหมวดเพียงพอ

## ชุดไอคอนประเภทข้อมูลที่แนะนำ

ใช้ SVG จากชุดเดียวกัน เช่น Lucide หรือ SVG ภายในโปรเจกต์ เพื่อให้ขนาด น้ำหนักเส้น และการแสดงผลสม่ำเสมอ

| หมวดข้อมูล | สัญลักษณ์ปัจจุบัน | แนวคิดไอคอนใหม่ | ความหมายที่ต้องสื่อ |
|---|---:|---|---|
| เรดาร์ฝน | `◉` | Radar | การกวาดตรวจฝนย้อนหลัง |
| น้ำท่วมจากดาวเทียม | `▧` | Satellite พร้อมพื้นที่น้ำ | ขอบเขตน้ำท่วมจากภาพดาวเทียม |
| พื้นที่น้ำท่วมซ้ำซาก | `▦` | History หรือ Calendar พร้อม Waves | การเกิดน้ำท่วมซ้ำตามช่วงเวลา |
| ปริมาณน้ำในเขื่อน | `▰` | Dam หรือ Reservoir | ปริมาณกักเก็บ น้ำเข้า และระบาย |
| จุดเฝ้าระวังน้ำท่วม | `≈` | Map Pin พร้อม Warning | จุดสถานีหรือถนนที่ต้องตรวจสอบ |
| ระดับน้ำแม่น้ำ | `≋` | Gauge พร้อม Waves | ค่าระดับน้ำในลำน้ำ |
| ฝนสะสม 24 ชั่วโมง | `☂` | Cloud Rain | ปริมาณฝนที่ตรวจวัดได้ |
| ระดับน้ำคลอง | `⌇` | Waterway | ระดับน้ำในคลอง |
| ประตูระบายน้ำ | `⊟` | Sluice Gate | ระดับน้ำหน้าและท้ายประตู |

ไอคอนเป็นส่วนเสริมเท่านั้น ต้องคงข้อความชื่อชั้นข้อมูลและ `aria-label` ที่ชัดเจนไว้เสมอ

## ระบบระดับสถานการณ์ที่แนะนำ

ใช้ทั้งรูปทรง สี และข้อความ เพื่อให้ผู้ใช้ที่แยกสีได้ยากยังอ่านสถานะได้

| ระดับ | รูปทรงแนะนำ | สี | ข้อความ |
|---|---|---|---|
| ปกติ | วงกลมพร้อมเครื่องหมายถูก | เขียว | ปกติ |
| เฝ้าระวังต่ำ | วงกลมหรือรูปตา | เขียวอมเหลือง | เฝ้าระวังต่ำ |
| เฝ้าระวัง | สามเหลี่ยมเส้นขอบพร้อม `!` | เหลือง | เฝ้าระวัง |
| สูง | สามเหลี่ยมทึบพร้อม `!` | ส้ม | สูง |
| วิกฤต | แปดเหลี่ยมหรือวงกลมทึบพร้อม `!` | แดง | วิกฤต |
| ไม่มีข้อมูล | วงกลมเส้นประพร้อม `?` | เทา | ไม่มีข้อมูล |

รูปทรงควรเปลี่ยนตามระดับ ไม่ใช้เพียงสีหรือความหนาของเส้น และต้องทดสอบที่ขนาดจริงบนแผนที่ซึ่งมีพื้นหลังหลายสี

## โครงสร้าง Legend ที่แนะนำ

แบ่ง Legend เป็นสองส่วน:

### ประเภทข้อมูล

แสดงไอคอนของเรดาร์ ดาวเทียม เขื่อน จุดเฝ้าระวัง แม่น้ำ ฝน คลอง และประตูระบายน้ำ พร้อมชื่อเต็ม

### ระดับสถานการณ์

แสดงสถานะปกติ เฝ้าระวังต่ำ เฝ้าระวัง สูง วิกฤต และไม่มีข้อมูล ด้วยรูปทรงและสีเดียวกับหมุดบนแผนที่

เพิ่มข้อความสั้นว่าระดับของแต่ละแหล่งคำนวณจากเกณฑ์ต่างกัน และการไม่พบจุดเตือนไม่ได้ยืนยันว่าไม่มีน้ำท่วม

## การแสดงสถานะเขื่อน

แยกสีเขื่อนออกจากสีเตือนภัย:

- ใช้แถบสีน้ำเงินแสดงสัดส่วนความจุ
- แสดงตัวเลขเปอร์เซ็นต์เป็นข้อมูลหลัก
- ใช้ลูกศรขึ้นหรือลงสำหรับแนวโน้มน้ำเข้าเทียบกับการระบาย
- ใช้ badge `100%+` เมื่อเกินระดับเก็บกักปกติ
- ใช้สีเตือนเฉพาะเมื่อมีเกณฑ์ภัยที่ได้รับการรับรอง ไม่ใช้เพียงเพราะปริมาณกักเก็บสูง

## ลำดับดำเนินการ

1. แยกไอคอนประเภทข้อมูลออกจากสัญลักษณ์ระดับสถานการณ์
2. เปลี่ยน Unicode เป็น SVG ชุดเดียวกัน
3. เลิกใช้ `≈` ในหลายความหมาย
4. ปรับ Legend ให้ครอบคลุมทุกแหล่งข้อมูล
5. แยกสีความจุเขื่อนออกจากสีระดับเตือนภัย
6. ทดสอบ desktop, mobile, high contrast และภาวะตาบอดสี
7. ตรวจด้วย keyboard navigation และ screen reader โดยคงข้อความและ `aria-label` ครบถ้วน

## เกณฑ์รับงาน

- ผู้ใช้ใหม่สามารถระบุประเภทชั้นข้อมูลหลักจากไอคอนได้โดยไม่ต้องเปิดคำอธิบายเพิ่มเติม
- สัญลักษณ์หนึ่งตัวมีความหมายหลักเพียงหนึ่งความหมาย
- ระดับสถานการณ์ยังแยกได้เมื่อแสดงแบบขาวดำ
- สีเขื่อนไม่ถูกตีความว่าเป็นระดับน้ำท่วมของพื้นที่
- Legend ใช้สัญลักษณ์ รูปทรง สี และข้อความตรงกับหมุดบนแผนที่จริง
- ไอคอนแสดงผลเหมือนกันบนเบราว์เซอร์หลักและไม่ขึ้นกับฟอนต์ระบบ

## สถานะการดำเนินการ (27 กันยายน 2026)

- ทำแล้ว: เปลี่ยน Unicode ทั้งหมดเป็น SVG sprite ชุดเดียวใน `frontend/index.html` คือไอคอนประเภทข้อมูล `i-*` และสัญลักษณ์ระดับ `sev-*`
- ทำแล้ว: `≈` ไม่ถูกใช้แล้ว โลโก้เป็นหยดน้ำ KPI จุดเตือนเป็นสามเหลี่ยมเตือน และจุดเฝ้าระวังเป็นหมุดพร้อม `!`
- ทำแล้ว: ระดับสถานการณ์ใช้รูปทรงตามตารางด้านบนในหมุด ปภ. และรายการจุดสำคัญ สถานี ThaiWater บน canvas ใช้รูปทรงชุดเดียวกัน คือวงกลม สามเหลี่ยม และแปดเหลี่ยม
- ทำแล้ว: legend แบ่งเป็น "ประเภทข้อมูล" และ "ระดับสถานการณ์" พร้อมหมายเหตุว่าแต่ละแหล่งใช้เกณฑ์ต่างกัน
- ทำแล้ว: เขื่อนใช้สีน้ำเงินสีเดียว มี badge `100%+` และลูกศรแนวโน้ม ไม่ใช้สีเตือนภัยแล้ว และเพิ่มภาพเขื่อนจริงจาก Wikimedia Commons พร้อมเครดิตและใบอนุญาต (`/api/v1/dams/photos`, `backend/app/data/dam_photos.json`)
- ยังไม่ได้ทำ: ทดสอบ high contrast ภาวะตาบอดสี screen reader และทดสอบกับผู้ใช้ใหม่ตามเกณฑ์รับงาน
