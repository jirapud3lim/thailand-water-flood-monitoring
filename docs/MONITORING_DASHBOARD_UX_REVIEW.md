# ผลตรวจ UX/UI สำหรับ Monitoring Dashboard

ตรวจวันที่ 27 กันยายน 2026 จากหน้าเว็บที่รันจริงที่ขนาด 1440 × 900 และ 390 × 844 พิกเซล และตรวจโค้ด `frontend/index.html`, `frontend/styles.css`, `frontend/app.js` การตรวจนี้ยังไม่แก้หน้าเว็บ

## สรุป

หน้าเว็บปัจจุบันเหมาะกับการสำรวจข้อมูลบนแผนที่ แต่ยังไม่เหมาะเต็มที่กับการเฝ้าระวังที่ต้องประเมินสถานการณ์เร็ว จุดที่มีผลมากที่สุดคือความสดและความครบของข้อมูลไม่ชัด แผนที่ระดับประเทศมีจุดทับกัน และตัวเลขเตือนยังไม่ช่วยจัดลำดับความรุนแรง

## สิ่งที่พบและข้อเสนอ

### P1 — แสดงความสดและความครบของข้อมูลให้ตรวจสอบได้

- ขณะตรวจ หน้าเว็บรายงานว่าขาด 2 จาก 5 แหล่งข้อมูล แต่ยังเน้นตัวเลข 87 จุดเตือน บนมือถือสถานะแหล่งข้อมูลเหลือเพียงจุดสี
- รายการสถานีมีเวลารายจุด แต่หัวข้อรายการแสดงว่า “ไม่ทราบเวลาข้อมูลสถานี ปภ.” ผู้ใช้จึงประเมินความสดของตัวเลขรวมได้ยาก
- แยก **เวลาวัดล่าสุด**, **เวลาที่ระบบดึงข้อมูล**, และ **สถานะสำรอง/ล้มเหลว** ต่อแหล่งข้อมูล แสดงสถานะนี้ใกล้ KPI และรายการจุดเตือน
- กำหนดเกณฑ์ข้อมูลเก่าสำหรับแต่ละแหล่ง แสดงป้าย “ข้อมูลเก่า” และลดน้ำหนักภาพของจุดเก่า แต่อย่าตีความว่าไม่มีน้ำท่วมเมื่อแหล่งข้อมูลล้มเหลว

ตำแหน่งที่เกี่ยวข้อง: `frontend/app.js` ฟังก์ชัน `renderHealth()` และ `renderPriority()`

### P1 — ลดจุดทับกันในแผนที่ระดับประเทศ

- ที่ระดับประเทศ หมุดจำนวนมากทับกันและบังจุดวิกฤต โดยเฉพาะบนมือถือ เรดาร์ยังเพิ่มความหนาแน่นของสีบนแผนที่
- รวมจุดตามพื้นที่เมื่อซูมไกล และแสดงจุดรายสถานีเมื่อซูมเข้า ให้จุดวิกฤตและระดับสูงมีลำดับภาพเหนือจุดทั่วไป
- แสดงจำนวนและระดับสูงสุดของกลุ่มจุด โดยกดกลุ่มเพื่อซูมหรือเปิดรายการในพื้นที่
- ทดสอบจำนวนจุดและความอ่านง่ายทุกระดับซูม โดยเฉพาะช่วงเปลี่ยนจากระดับ 6 เป็น 7

ตำแหน่งที่เกี่ยวข้อง: `frontend/app.js` ฟังก์ชัน `loadFloodPoints()` และ `loadThaiWater()`

### P2 — ทำให้ตัวเลขเตือนช่วยจัดลำดับงาน

- ตัวเลข “จุดเตือน” รวมระดับเฝ้าระวังต่ำถึงวิกฤต จึงไม่บอกว่าจุดใดต้องตรวจดูก่อน
- แยกจำนวน **วิกฤต / สูง / เฝ้าระวัง** และระบุชัดว่าเป็นสถานีในขอบเขตแผนที่ปัจจุบัน ไม่ใช่ประกาศเตือนภัยทางการ
- เพิ่มตัวกรองจังหวัดหรือพื้นที่ ประเภทสถานี ระดับความรุนแรง และความสดของข้อมูล
- ให้รายการจุดแสดงค่าที่วัด เกณฑ์ที่ทำให้เข้าระดับนั้น และเวลา โดยไม่ต้องเปิด popup ก่อน

ตำแหน่งที่เกี่ยวข้อง: `frontend/index.html` ส่วน KPI และรายการจุด, `frontend/app.js` ฟังก์ชัน `renderPriority()`

### P2 — วาง legend และสถานะใกล้ข้อมูลที่อธิบาย

- Legend ปัจจุบันอธิบายจุด ปภ. อยู่ท้าย sidebar ส่วนสีเรดาร์และ ThaiWater ไม่มีคำอธิบายที่มองเห็นพร้อมแผนที่
- แสดง legend ตามชั้นข้อมูลที่เปิด ใกล้แผนที่หรือในแผงที่เรียกได้ทันทีบนมือถือ
- ใช้ข้อความหรือสัญลักษณ์ร่วมกับสีเสมอ และตรวจขนาดตัวอักษรประกอบที่ปัจจุบันบางส่วนประมาณ `0.63rem`

ตำแหน่งที่เกี่ยวข้อง: `frontend/index.html` ส่วน legend, `frontend/styles.css` ส่วน `.section-help`, `.map-radar-status`

### P2 — จัดหน้ามือถือให้เห็นสถานะก่อนการสำรวจ

- เมื่อเปิดแผงด้านข้าง รายการจุดสำคัญกินพื้นที่ก่อนตัวกรองชั้นข้อมูล ผู้ใช้ต้องเลื่อนเพื่อเปลี่ยนชั้นแผนที่
- คงสถานะแหล่งข้อมูลเป็นข้อความสั้นที่มองเห็นได้ ไม่ใช้เพียงจุดสี
- พิจารณาแยกแผงมือถือเป็น “สถานการณ์”, “ชั้นข้อมูล”, และ “รายละเอียดจุด” โดยคงปุ่มกลับแผนที่ที่ชัดเจน

## ข้อจำกัดและงานที่ค้าง

- ตัวเลข 87 จุดและ 2/5 แหล่งเป็นภาพขณะตรวจ ไม่ใช่ค่าคงที่
- ยังไม่ได้ทดสอบกับผู้ใช้จริง เครื่องอ่านหน้าจอ หรือเครือข่ายช้า
- แก้แล้ว (27 ก.ย. 2026): บัคคำขอ ThaiWater เก่าที่อาจวาดชั้นข้อมูลกลับมาหลังปิดหรือซูมออก `loadThaiWater()` ใช้ request id ต่อชั้นข้อมูลและทิ้งผลตอบกลับที่มาช้า (`frontend/app.js`)
- ขอบเขตน้ำท่วม GISTDA ยังไม่ได้เชื่อมต่อ การไม่มีชั้นนี้ไม่ใช่หลักฐานว่าไม่มีน้ำท่วม
